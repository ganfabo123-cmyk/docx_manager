# BaseAgent 需求文档

## 1. 背景

本项目需要在多个模块（FormulaGenerator、TableGenerator、ImagePositionGenerator）中调用远程大模型平台。为避免重复实现 HTTP 通信逻辑、统一错误处理方式，抽象出 `BaseAgent` 作为唯一的大模型通信基础层。

上层模块不直接依赖 `BaseAgent`，而是通过 `llm_router.py` 中的路由函数间接调用，实现业务逻辑与通信细节的解耦。

---

## 2. 功能需求

### 2.1 核心通信
- 能够向指定的远程大模型平台发送 HTTP 请求
- 支持传入 `user_prompt` 和可选的 `system_prompt`
- 返回模型的回复文本（纯字符串）

### 2.2 请求构造
- 将 prompt 按平台要求的格式组装为请求体
- 支持在初始化时指定模型名称（如平台支持多模型）

### 2.3 响应解析
- 从平台返回的响应中提取模型回复文本
- 屏蔽平台响应结构的差异，对上层始终返回统一的字符串类型

### 2.4 鉴权
- 支持在初始化时传入 API Key 或其他鉴权凭证
- 鉴权信息通过请求头（或其他平台指定方式）携带

### 2.5 错误处理
- HTTP 请求失败（网络异常、超时）时抛出可识别的异常
- 平台返回非预期响应结构时抛出可识别的异常
- 不在内部静默吞掉错误，交由调用方决策

---

## 3. 非功能需求

| 项目 | 要求 |
|------|------|
| 可配置性 | endpoint、api_key、model 均在初始化时注入，不硬编码 |
| 单一职责 | 只负责通信，不包含任何业务 prompt 逻辑 |
| 可测试性 | HTTP 层可被 mock，方便单元测试 |
| 无状态 | 每次 `chat()` 调用独立，不维护多轮对话上下文 |

---

## 4. 约束与假设

- 平台通信协议为 HTTP/HTTPS，请求体为 JSON 格式
- 当前不要求支持流式（streaming）响应，按需后续扩展
- 平台的具体请求/响应字段格式**待确认**（见接口文档中的 [待确认] 标注）
- `BaseAgent` 不负责 prompt 的业务内容，由 `llm_router.py` 负责

---

## 5. 依赖关系

```
llm_router.py
    └── BaseAgent          ← 本模块
            └── 远程大模型平台（HTTP）
```
